# Social contextual AI runtime boundary

Social consent transactions now check the canonical M2 Social lifecycle, current controlled module epoch, private profile ownership, recorded adult eligibility and opt-in, and current Social restrictions. The module epoch rotates in the transaction that changes the canonical lifecycle or Social starter selection. Superseded pending consent is revoked durably. These checks complement independent session, conversation and interaction guards.

Activation still requires two sources that are absent on Develop. M2's module lifecycle writer is isolated to disposable test hosts and there is no authoritative application session ledger connected to verified login, logout and account switching. The existing JWT and confirmed-user verifier do not establish a durable logout epoch. M4's chat access reader and storage are candidate contracts without a deployed conversation authority or a shared revocation transaction. The current M1 Learning AI storage is tied to Learning ownership. No separate replacement M4 conversation system or fabricated Social conversation is introduced.

The consent repository uses one transaction for state, replay handling, attempt admission, decision audit and revocation fences. The admission and late-reply callbacks require an implementation on that same transaction. PostgreSQL tests supply explicit fixture-only conversation, session, interaction and budget fences. Production registration, consent/status HTTP operations and generation remain unavailable until those authorities and the applicable privacy notice, quota, budget, late-reply and data handling contracts are integrated. Participant and Group messages remain outside Social contextual AI.

M2's existing controlled HTTP host exercises activation, deactivation and reactivation with its actual PostgreSQL lifecycle writer and the Social consent schema on the same database. Activation and reactivation create new epochs. Deactivation durably revokes pending consent, and reactivation cannot restore the old epoch. The test authenticates the lifecycle caller and uses explicit fixture policy evidence. The live starter endpoint accepts the original selection and denies a different selection. Production switching, authentication-session revocation, and Contextual AI routes still depend on deployed M2 authorities.
