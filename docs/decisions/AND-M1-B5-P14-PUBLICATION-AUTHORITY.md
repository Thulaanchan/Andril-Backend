# Ordinary Learning disclosure and voluntary offer publication

Implements the confirmed AND-M1-B5-P11-20261128 decisions. No additional business
approval is asserted or requested. New technical mappings are explicit below.

- People publication requires separate explicit visibility and ordinary-display-name
  disclosure. Names come only from the current owner's M2 Learning DisplayName;
  ownership, account, module and content cannot be supplied in the publication body.
- M2 private profiles remain private. `DisplayNames.Validate` permits only `private`;
  no public profile state is invented. The dedicated ordinary-purpose grant exposes
  only the approved profile reference and reviewed display name, never Bio or other data.
- Current shared account discoverability must be public, with GhostMode off. Missing
  settings and unresolved contacts-only disclosure remain withheld. These settings
  alone never authorize disclosure. Current M2 age/membership/lifecycle/Terms/Privacy
  and M5 restriction/symmetric-block evidence are checked independently.
- Stored name review binds exact source text. Name changes withhold output until
  explicit renewal. Publication binds the M2 lifecycle revision: reactivation alone
  cannot resurrect a prior grant. Durable generation/version CAS rejects stale/ABA
  changes; revocation preserves the record and source data, with no retention policy.
- Mentorship publication binds the owner's exact existing voluntary offer (kind 4).
  Growth records and foreign offers cannot be published. The backend proof reader
  checks exact published offer identity and current eligible/unblocked participants.
  Publication is separate from ordinary name disclosure, requests and AI processing.
- Both producer and People reader reuse the delivered pre-snapshot M5 authority fence
  and M2 serializable owner boundary. Source revocation and reads serialize; source
  locks survive private scope deletion until callback release. No automatic retries.
- Private backend/transaction/caller/target/resource leases allow exact M2 lifecycle
  and published-offer reads. PostgreSQL FOR SHARE additionally needs UPDATE USING:
  the exact publication-row lock policy has WITH CHECK false, forbidding cross-owner
  rewrites. Runtime has no identity, private-offer or scope-table SELECT, DELETE,
  ownership rewrite, BYPASSRLS or generic source-authority grants.
- The existing LearningPeopleDiscoveryService and its output filtering are reused
  through a real M2 read lease. A nonce labels that ephemeral verified callback; it
  is not a persisted revision, cached permission, AI consent or source publication.
- `Learning:Publications:Enabled` defaults off; its restricted RuntimeRole is explicit.
  Migration preparation requires existing M2 privacy, M5 authority, Learning and private
  owner-activity migrations. No startup/hosted migration or live activation occurs.
