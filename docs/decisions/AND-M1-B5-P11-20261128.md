## Implemented scope and technical choices

The existing mentorship comparison and isolated persistence now reject any second
pending request for the same unordered pair. A database unique index supplements
transaction coordination. Terminal requests do not prevent a new request. This
does not publish private offers or install a permissive production peer authority.

The opt-in `Learning:XpRead` composition exposes only authenticated current-owner
balance/history/progress. It shares the delivered M2 serializable authorization,
subject fence and restricted-role boundary. Its separately versioned ledger
migration requires deployment preparation; no startup/hosted migration runs.
The runtime receives SELECT only. Award, adjustment and policy publication stay
unavailable; no synthetic earning policy is registered. Levels, achievements and
policy revision remain unspecified in the read projection. Synthetic credits in
tests are fixture-only. Stable UUID paging follows the existing repository contract.
